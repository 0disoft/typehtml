## 개선한 8개 항목

아래 시간은 같은 프로세스에서 합성 데이터를 반복 처리한 중앙값이다. 실제 서비스 부하, 디스크 내구성 또는 다른 OS의 지연을 보장하지 않는다. 소스 비교용 변형은 메모리 안에서만 만들었다.

## 적용 한계

- 4 MiB는 compact submissions 배열의 상한이다. 전체 보고서나 들여쓰기한 JSON의 상한이 아니다. 경로/방문 예산과 함께 사용한다.
- 세션 배치는 호출당 연속 점유 시간을 줄인다. 전체 삭제 처리량이 향상되었다는 측정은 아니다. 취소 전에 완료한 배치는 커밋된 상태로 남는다.
- intent fallback은 만료된 손상 행이 많으면 해당 후보 수에 비례한다. 모든 데이터 분포에서 O(배치 크기)라고 주장하지 않는다. 새 인덱스 두 개의 저장 공간과 쓰기 유지 비용이 추가된다.
- Node 22, 다른 OS, 실제 운영 트래픽, P0a/P0b 제품 비교는 이번에 검증하지 않았다. npm 공개 배포와 Git push도 실행하지 않았다.
