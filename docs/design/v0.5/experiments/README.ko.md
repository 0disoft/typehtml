# P0는 계획이며 아직 측정하지 않았다

[p0-plan.json](p0-plan.json)은 B/L/S/D 네 도구 구성과 11개 작은 비교·대조 사례를 정의한다. 제품 앱을 네 개 만드는 계획이 아니다. 세 핵심 변경, 세 공로/정상 대조군, 두 정상 제출 사례, 세 unknown/unsupported 사례다.

[도입 조사 양식](adoption-inventory.template.json)은 실제 폼 제출 경로 최대 10개를 기록한다. 실제 프로젝트를 읽지 않았으므로 rows는 비어 있고 측정값은 null이다. 기존 도구와 schema가 무엇인지 확인하기 전 Doctor의 적합성을 결정하지 않는다.

[결과 양식](results.template.json)은 모든 구성의 status가 NOT_RUN이다. 결과가 없음을 0건 발견으로 해석하지 않는다. 실행할 때 원본 양식을 복사하고 기준 commit·변경 diff·원시 로그·도구 버전·설정 해시·수동 비용을 채운다. 같은 원인에 대한 tsc·lint·스크립트·Doctor의 출력을 한 결함으로 묶는다.

구판 three-changes.json의 C1은 유지하고, 기존 C2와 C3는 각각 N1과 N2로 옮겼다. 새 C2는 submitter 경로 불일치, 새 C3는 제한된 제약 반례다. 구판과 결과 ID를 혼합하지 않는다. 서버 생성기·DB 성능·시장성은 이 실험 대상이 아니다.

S와 D 모두 같은 schema·metadata·표준 parser를 이용할 수 있다. S를 약하게 만들려고 줄 수 제한이나 정규식만 사용하라는 제약을 넣지 않는다. 필요한 도구가 없으면 추가 발견 판정은 보류하고, 합성 결과로 실제 결함 빈도를 추정하지 않는다.
